# Realsee → 可编辑 Blender 空间

[English](SKILL.md)

尽早交付整体可信、可以使用的空间模型，再精修对用户最重要的部分。把用户采集的空间重建为可以继续在 Blender 中修改的原生场景。优先完成空间布局、墙体、地面、顶面、开口与固定设施；家具和小物件按用户要求的深度补充。实际执行 Blender、查看输出并修正；计划、脚本或保存一次扫描导入都不是重建成果。

## 默认工作方式：整体优先，选择性精修

按用户实际要看的视角和要做的编辑确定细节深度，不以放大每张源图后的最大细节为目标。开始时阅读[高效建模与预览流程](references/fast-workflow.zh-CN.md)；大量创建对象或排查迭代缓慢时阅读[自动化性能](references/automation-performance.zh-CN.md)。

- 尽早给出覆盖**全部**目标区域、关闭扫描参考后的整体预览，使用真实开口和简单原生几何。不能一边精修某房间的小配件，一边让其他房间缺结构。blockout 是有效检查点，不是最终交付。
- 先修尺度、连通关系、墙与开口轮廓、大面积饰面和主要光照，再考虑微小倒角、标签、划痕、瓶中内容或隐蔽五金。细节影响目标编辑、接触、阴影、反射、轮廓或特写时，再增加投入。
- 使用满足需求的最简单原生构造。重复组件与材质复用；不需要几何编辑的表面凹凸用贴图或 bump/normal 表达。必须存在的开口或独立组件不能用平面图替代。
- 针对当前决策查最有用的来源，选一个规范扫描并使用轻量工作参考。只有为解决具体疑点或用户明确要求时，才深查 RAW、每种重复导出或全分辨率点云区域。
- 成批完成相关修改，再看整体与改动区域。维护简短、按影响排序的可见或功能问题列表，每轮明确修一个问题；优先修补保存的场景，不反复全量重建。
- 某部分达到目标用途，且其他未解决问题更重要时，停止对它精修。低影响细节不明确或反复修改没有实质改善时，保留有依据的近似、简要说明并继续。不要制造精度，也不要追求与照片逐像素相同。
- 最后做代表性的真实编辑检查和简洁、诚实的交付。检查通过、目标结果达到后就交付，不为了继续工作而新增可选审计或装饰轮次。用户明确要求完整逐项重建或工程检查时仍以其要求为准。

对已有场景做局部修改时，检查目标及其依赖，在保留原件的副本上修改并验证结果。只改一面墙的颜色，需要看真实着色结果、数据共享关系、保存后是否保留及相邻表面是否未受影响，不因此重做来源配准或全场几何编辑测试。复用已有验收证据，只重跑失效检查；没有旧检查记录时，说明本次实际验证范围，不声称重新认证了整个场景。

## 确认项目与范围

从会话中选择的项目目录确定 `PROJECT_ROOT`，不要使用 skill 安装目录。相对输入输出路径均以项目根目录解析。优先遵循用户指定的路径，否则检查 `data/`，交付 `output/reconstruction_native.blend`。资料不存在时说明具体缺什么，不创建空目录后把它当作已有证据。保留原始输入和用户已有模型。

用户提供项目说明或验收要求时先阅读，范围与容差以其要求为准。不要把原案例的房间清单、尺寸、机位数量、统一 10 毫米容差或 Goal 模式设置作为默认要求。只有用户请求且工具确实支持时才启用持续目标。

从 PATH、用户指定的可执行文件或已有本地集成中发现 Blender 并核实版本，启动前解析可执行文件的符号链接。后台 `bpy` 不依赖 MCP。导入、材质、渲染设备和导出的调用以实际安装版本的 API 为准。脚本、检查点与预览存放在项目内，不写入 skill。

## 从证据重建

开始或修正场景时阅读[来源配准与原生建模](references/reconstruction.zh-CN.md)。

1. 简要盘点有实质内容的输入、用途、重复关系、依赖和检查状态，按任务需要再深入，保留贴图相对路径。同一扫描的多个格式不是多个物理空间。
2. 在精细建模前确定单位、竖直轴、左右手系、原点、地面基准、来源到场景的变换与可靠对应点。图纸提供标注尺寸，点云和网格提供三维表面，照片提供外观。明确来源之间的重要冲突，不靠调缩放掩盖矛盾。
3. 识别有证据的区域与连接，维护从现场要素到实际对象 ID 的简洁覆盖记录，区分测得、推断和未解决。全景机位不是房间数，反射不是额外房间。
4. 先搭完整的目标结构，再逐区域装饰。使用原生 Mesh/Curve、材质节点和有实际用途的可编辑修改器。门扇与门框分离，铰链位置正确，可独立编辑的表面和组件保持分离。不能用整块三角扫描或平面贴片代替结构。
5. 将配准后的扫描与原始贴图保留在明确命名的参考集合或随附参考文件中，默认不参与最终渲染。关闭参考后重建空间仍应完整；保留未经修改的原始数据，单独记录配准。
6. 先比较平面、立面和中性实体视图，再通过矫正照片或配准机位逐区域比较室内，修正形状、饰面与实际光源位置。在有意义的阶段展示简洁预览并落实用户反馈。

分派区域或资产建模时，向各执行者提供统一坐标系和稳定对象 ID，使用独立输出文件，由一个集成人员负责合并。不要让多个执行者同时写同一 `.blend` 或操作同一个 Blender 实时场景。

持续完成已授权的重建与修正，不停在 blockout。证据或工具阻碍某部分时继续独立工作并说明具体缺口，不把推断细节称为实测复刻。

## 验证保存后的交付物

交付前阅读[验收与重开编辑测试](references/acceptance.zh-CN.md)。对于重建交付，最终候选就绪后执行一次新进程重开、代表性几何/材质编辑、保存及再次重开检查；只有后续改动使其失效时才重做。要声称原生可编辑，这些实际检查不可省略。单纯移动对象不够。最终交付原设计状态，不把编辑测试副本当最终模型。

检查请求范围内的空间及结构连接、关键来源与模型尺寸、资源加载、材质和关闭参考后的渲染。说明不确定处与未执行检查；报告深度与任务相符，不为报告而制造精度或冗长审计。

交付 `.blend`、必要的打包或相对路径资源、对比图、实际使用的脚本和简洁编辑说明。可编辑重建、照片级逼真和尺寸一致分别需要证据，不混为一个结论。

## 按需扩展

仅在相关请求中阅读[漫游、物理、生成资产和网页预览](references/extensions.zh-CN.md)。生成资产、视频和网页 GLB 都不替代原生可编辑场景。不要因本地建模任务自动上传扫描、购买生成额度、公开文件或更改全局 GPU/代理设置；这些操作遵循用户的实际授权。
