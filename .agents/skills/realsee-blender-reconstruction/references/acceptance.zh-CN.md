# 验收与重开编辑测试

[English](acceptance.md)

## 让验证投入与请求相符

普通可编辑空间交付，检查关键尺寸与连接、各区域代表视图、资源加载，以及代表性几何/材质编辑的保存持久性。复用建模阶段已有对比，不每次微调都跑整套重开编辑测试；最终候选执行一次，相关数据变化后只重做受影响的检查。

全点云距离统计、穷尽拓扑报告、每个采集机位和逐物件照片检查，仅在明确工程/完整验收要求或具体错误待排查时开展，不作为默认前置条件。目标细节层级之外的小外观不确定性不阻碍可用交付；缺少目标房间/开口、贴图损坏或编辑失败仍需解决。这里是在选择工作范围，不代表省略的检查已经通过。

针对已有场景的局部修改，验证改动数据、保存后状态、可见结果及应保持原样的相邻组件。复用已有验收证据，单改材质不重跑无关的几何编辑测试。没有旧测试记录时，说明本次验证范围，不自动开启全场审计，也不声称整场已通过。

## 检查重建本身，而非参考叠加

最终视图关闭原扫描和旧检查点。检查展示空间连接的平面图、有意义的立面、中性实体/线框视图，以及目标区域的室内图。用相同位置与方向对比源照片；没有配准的漂亮视角不能证明对齐。除了显眼的家具，也要看顶面、地面、开口、门背和角落。

覆盖记录必须落到实际对象 ID，分别说明缺失的目标组件、未解决资料缺口及推断补全。总对象数不能代替覆盖检查。遵循用户指定容差，否则按资料质量和测量定义报告有意义精度的实际偏差，不把建模目标称为测绘精度。

需要点云距离分析时，应说明配准、来源区域、采样密度/方法与被比较的重建表面，报告中位数和较高百分位等稳健统计，不只给有利的平均值。区分缺测、噪声和真实偏移，不能为降低误差而剔除矛盾点。

## 用新进程检查保存文件

保存预定交付物，关闭后用新的 Blender 进程打开这个确切路径。使用实际发现的可执行文件并保留错误；脚本退出成功而未检查保存文件不够。典型启动形式：

```text
<discovered-blender> --background --factory-startup --python-exit-code 1 --python <project-check-script>
```

项目检查脚本应通过 Blender 原生 API 打开明确的交付路径，核对加载路径、参考可见性、集合层级、可编辑数据/修改器、目标组件 ID、材质及其实际使用的图像。检查外部资源和打包图像，有 UDIM 或链接库时也检查其依赖。新进程中渲染一张关闭参考的小图。缺图、断开的链接资产或只能依赖插件显示的几何应修复后再声称可独立打开。

先看结构实体的可见开洞、穿插与着色错误；拓扑、修改器、导出或用户要求的加工/模拟确有需要时，开展针对性几何检查。同时考虑求值后结果和合理开放表面，不对所有对象套同一封闭性规则。

## 在一次性副本上证明独立编辑

从当前场景选测试对象，不硬编码案例名称。记录基准变换、相关顶点或修改器值、材质分配，以及应保持不变的相邻组件。如果没有证据支持或范围不含门、家具，对应操作标为不适用；合适时选择其他可独立操作或带材质组件，不为测试凭空造一个。

1. 从重开的最终场景修改一段真实墙体或开口的局部几何/原生参数，确认形状或开口实际变化；单纯平移不算。
2. 绕铰链旋转有证据的门，核实铰链点和门框不动，门扇附件随动。
3. 范围内有家具时，独立移动一件并修改其分配材质。检查共享网格和材质数据块；独立编辑需要时建立单用户副本，确认无关组件不变。贴图连接可能覆盖底色默认值，应检查实际材质结果。
4. 如果重建交付物除隐藏参考外还包含复用扫描/生成网格，对其中代表对象通过 Edit Mode 或原生网格 API 修改顶点或面并确认保存，不能用对象变换证明拓扑可编辑。
5. 保存到独立测试 `.blend`，退出，再用另一个新进程打开，核对预期编辑和应保持不变的邻居，记录有用的前后对比。
6. 确认原交付物仍为预期未修改状态，例如比较测试前后的文件哈希。测试文件与最终产物分开。

报告实际执行并持久化的操作、对象、变化和失败。合成立方体/墙体的小测试只验证 Blender 执行环境，不能替代对真实交付场景的编辑。

## 最终交付

给出原生场景、必要资源或随附参考文件、少量来源对比、实际执行脚本和简洁编辑说明：结构/参考在哪个集合，如何修改墙体、开口、材质，以及有要求时动画和物理在哪里。说明覆盖及尺寸/视觉差异，不承诺无证据的完美复刻。必要条件未通过时明确说尚未完成，并指出下一步所需资料或工具动作。
